# Testing Strategy

The Gondor Ecosystem uses a layered testing strategy that progressively increases confidence from isolated unit logic to full end-to-end blockchain integration.

---

## Testing Layers

| Layer | Tool | Scope | Infrastructure Required |
|---|---|---|---|
| Unit (Go) | `go test` + `gomock` | Domain services, fallback logic, Merkle tree, receipt signing | None (pure memory) |
| Smart contract | Hardhat + Chai (TypeScript) | Solidity contract functions, SBT properties, verifier interface | EVM in-memory (Hardhat) |
| Integration (Go) | `go test` + mocks | Service interaction across modules | None |
| End-to-end acceptance | Testcontainers-Go + Anvil | Full pipeline: trade → sign → batch → anchor → ZK prove → verify on-chain | Docker (MySQL + Anvil) |
| Stress / Load | Custom Go simulator (`cmd/simulate`) | Throughput, concurrency, API quota behavior | Docker + Local blockchain |

---

## Unit Tests (Go)

**Philosophy**: Maximize coverage of real application flows without depending on external services. Mock only at port boundaries (Go interfaces).

**Coverage achieved**:
- >85% on service layer (`TransactionService`, `StockService`, `AuthService`, `HoldingService`, etc.)
- >70% on API controllers and persistence adapters
- 100% on testable infrastructure (everything except live HTTP clients to external APIs)

**Key techniques**:
- `gomock`-generated mocks for all Hexagonal Architecture port interfaces (`IdentityBridge`, `PolygonClient`, `StockRepository`, etc.)
- **Golden files**: REST API response payloads are validated against stored reference files, enabling deterministic regression detection across releases.
- **Isolated Merkle tests**: The Poseidon Merkle tree construction and proof generation are tested independently, validating root computation and inclusion proof correctness for edge cases (single leaf, full 1024-leaf tree, zero-padded trees).

---

## Smart Contract Tests (Hardhat)

**Framework**: Hardhat + Chai + TypeScript  
**Pattern**: Fixtures — each test deploys a fresh contract instance for complete isolation.

**Key test cases**:

| Test | What it validates |
|---|---|
| SBT non-transferability | `transferFrom` reverts with `"Gondor: SBT is non-transferable"` |
| Sovereign Handover | After `sovereignHandover`, new owner still cannot transfer the token |
| Heartbeat expiry | `isReputationExpired()` returns `true` after interval; `revokeExpiredReputation` resets levels to 0 |
| Merkle root anchoring | `anchorRoot` correctly registers root in `canonicalRoots` |
| ZK proof verification | `MockVerifier` with configurable pass/fail response validates the `updateReputationWithProof` path |
| Double mint prevention | Attempting to mint a second SBT to the same wallet reverts |

---

## End-to-End Acceptance Tests (Testcontainers)

**Framework**: [`testcontainers-go`](https://golang.testcontainers.org/) — spins up real Docker containers programmatically within the test suite.

**Infrastructure provisioned per test run**:
- MySQL container (initialized with `db/schema.sql`)
- **Anvil** (Hardhat local EVM node) container — full deterministic blockchain, no external network

**What the acceptance tests validate**:

The full `Verify-me` pipeline for a real user lifecycle:
1. Register user → SBT minted on Anvil → MySQL updated with `SbtTokenID`.
2. Execute N trades → signed receipts returned → stored in MySQL.
3. Batch complete → Merkle tree built → root anchored on Anvil via `anchorRoot`.
4. ZK proof generated by SnarkJS → submitted via `updateReputationWithProof`.
5. On-chain Groth16 verifier accepts the proof → `reputationLevels` updated.

**Test scenarios**:

| Scenario | Validates |
|---|---|
| ROI = +99% (profitable batch) | Positive ROI path, correct accumulation in circuit |
| ROI = −50% (losing batch) | Negative ROI modular arithmetic in BN254 field |
| Interleaved users (multi-user batch) | `userID[i] === tokenId` constraint — cross-user transactions rejected |
| Heartbeat expiry + active cron | `HeartbeatCron` forces batch completion with dummy transactions |

## Stress Simulator (`make simulate`)

A custom Go script in `cmd/simulate` that acts as a client against a live local deployment:

1. Registers N users via `POST /register`.
2. Waits for SBT confirmation on-chain for each user.
3. Submits a stream of interleaved buy and sell orders across all users.
4. Monitors throughput, API response times, and Redis cache behavior via the `go-metrics` instrumentation.

This simulator was used to measure the Fan-in/Fan-out concurrency performance and to validate the Redis cache strategy under realistic concurrent load.

## Experimental Results Summary

### Blockchain Gas Costs

| Operation | Mean Gas | Estimated Mainnet Cost* |
|---|---|---|
| `safeMint` (SBT creation) | 213,721 | $0.00288 |
| `anchorRoot` (Merkle anchoring) | 47,680 | $0.00064 |
| `updateReputationWithProof` (ZK) | 363,294 | ~$0.00490 |
| **Full user lifecycle** | **~624,695** | **~$0.0085** |

*30 Gwei, POL = $0.45*

### ZK Proof Generation Latency (92 samples, Intel i7 @ 2.8 GHz, CPU-only)

| Phase | Mean | Std Dev | Min | Max |
|---|---|---|---|---|
| Witness generation | 921 ms | ±489 ms | 304 ms | 2,670 ms |
| Groth16 proof | 13,596 ms | ±6,341 ms | 5,118 ms | 31,800 ms |
| **Total off-chain** | **14,586 ms** | **±6,531 ms** | **5,445 ms** | **32,840 ms** |

Proof generation is fully **asynchronous** — it does not block user trade execution.

### Comparative Analysis (Gondor vs. State of the Art)

| Dimension | **Gondor** | Sismo (Hydra-S1) | Worldcoin (Semaphore) | Spectral / ARCx |
|---|---|---|---|---|
| **Gas (on-chain verification)** | ~363K | ~300K | ~200K | N/A (off-chain oracle) |
| **Proof size** | ~805 bytes | ~256 bytes | ~256 bytes | N/A |
| **Private data hidden** | Full history (8 fields × 5 tx) | 1 membership nullifier | 1 binary signal | None (public) |
| **Dynamic reputation update** | ✅ Continuous batch + Heartbeat | ❌ Point-in-time snapshot | ❌ Single signal | ✅ (but public) |
| **Inactivity penalty** | ✅ On-chain (30 days configurable) | ❌ N/A | ❌ N/A | ⚠️ Partial (ARCx: 120 days) |
| **Full lifecycle cost (L2)** | ~$0.0085 | ~$0.0041 | ~$0.0027 | ~$0.001 |

Gondor's higher gas cost vs Sismo/Worldcoin is a direct consequence of **richer semantic content**: the circuit validates 5 transactions × 8 fields, 5 EdDSA signatures, 5 Merkle proofs, and 3 ROI aggregates — substantially more than a single membership bit or binary signal.
